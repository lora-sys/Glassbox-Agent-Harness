# Task: P2.7 — Measure the performance redline (synthetic 1000+ event session)

AGENTS.md now has the redline: "a session with 1,000 or more trace events and 10 or more turns keeps Canvas interactions (select, pan, zoom, inspector open) responsive. Measured once at phase acceptance, recorded, no speculative optimization before it fails." This slice performs that measurement. The upstream model API is currently overloaded, so this measurement must be fully synthetic (no live provider turns).

## Steps
1. Build a synthetic session generator: a small script (apps/server/src/scripts/gen-synthetic-train.mjs or a test helper) that writes a trace.jsonl with 1200+ realistic events across 12+ turns (turn/started, item/started, agentMessage deltas, item/completed, fileChange, turn/completed, a few action records) directly via RawTraceStore or the same JSONL format. Use the existing schema shapes from apps/server/src/codex/schema.ts so replayTrace handles it.
2. Serve it: start apps/server, create the synthetic session (the generator can write directly under .glassbox/sessions/<id>/ — reading it back is via GET /state and GET /trace which the web already supports).
3. Measure with Playwright (apps/web/e2e/p27-perf.spec.mjs): open the app with ?session=<synthetic-id>, wait for shapes, then measure with page.evaluate + performance.now:
   - select a shape (editor.select + selection latency)
   - pan (mouse drag) and zoom (wheel) round-trip frames
   - open the Inspector for an artifact-like shape (read [data-glassbox-inspector] textContent timing)
   - WS replay: time from page load to shapes rendered (initial reconstruction cost for 1200 events)
   Record p50/p95 for each over ~20 iterations.
4. The pass bar: interactions feel responsive — define concretely as p95 under 250ms for selection and inspector open, pan/zoom without main-thread blocks over 500ms, initial render under 5s. Report the actual numbers honestly; if a bar fails, record WHICH and by how much (per the redline: no speculative optimization now — the failure just becomes the next plan's first ticket).
5. Write the numbers into .plans/findings/02-p2.7-perf-redline.md (method, machine context one-liner, results, verdict) and append progress to .plans/findings/_p2.7-progress.md.

## Safety
- The synthetic session lives under <repo>/.glassbox/sessions/ (gitignored). No live provider calls anywhere in this slice.
- Modify apps/server (script/helper only), apps/web (perf e2e only). No AGENTS.md, README, Notion.
- Stop only processes you start, by PID. Follow AGENTS.md.

## Working style
Budget: within 45 minutes. Append progress per step.

## When done
Print: the redline results table (p50/p95 per interaction), the verdict (pass/fail per bar), the findings file path.
