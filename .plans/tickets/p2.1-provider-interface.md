# Task: P2.1 — Extract the provider interface from CodexAdapter (zero behavior change)

Phase 2 adds a second provider (Claude Code). Before writing it, extract the minimal provider interface that CodexAdapter already implements, so the next slice can add ClaudeCodeAdapter behind the same seam. Read .plans/findings/02-p2.0-claude-code-spike.md first for context (T3 Code patterns are vendored in upstream/t3-code/).

## Rules
- ZERO behavior change. This is a pure refactoring slice: extraction and renaming only, no logic edits, no codex-ism removal beyond naming.
- All 53 server tests must stay green. The S8 e2e must still pass conceptually (no need to run it; the unit suite plus typecheck is the guard, but run the server vitest).

## Steps
1. Read apps/server/src/codex/adapter.ts and apps/server/src/index.ts. Enumerate the public surface index.ts actually uses on the adapter: thread/start, turn streaming, interrupt, decision response, approval event subscription, turn-end hooks, workspace snapshot/scan, process lifecycle.
2. Create apps/server/src/provider/types.ts defining a minimal ProviderAdapter interface covering exactly that surface, named in provider-neutral terms (session/thread, turn, streaming normalized events, decision). Use Glassbox vocabulary from AGENTS.md (session, run, turn, event, provenance). Keep it small: if a method is only used by codex today and has no claude equivalent, leave it on CodexAdapter (not the interface) and note why in a comment.
3. Mark CodexAdapter as implementing the interface (`class CodexAdapter implements ProviderAdapter`). Adjust signatures only where the interface demands a neutral name; do not rename internal codex wire terms.
4. Update index.ts to type its adapter reference as ProviderAdapter. Add a tiny factory (createAdapter(provider: "codex" | "claude-code")) that returns CodexAdapter today and throws "not implemented" for claude-code. index.ts calls the factory with "codex" — no behavior change.
5. Do NOT create the ClaudeCodeAdapter in this slice. Do not add the SDK dependency yet.
6. Run npx vitest run apps/server/src --reporter=basic from the repo root: 53/53 (2 integration may skip). Also run a TypeScript check on apps/server (npx tsc --noEmit -p apps/server or equivalent) and fix any type fallout of the extraction.
7. Append progress to .plans/findings/_p2.1-progress.md as you go.

## Deliverables
- apps/server/src/provider/types.ts (the interface)
- CodexAdapter + index.ts wired through it
- Factory with claude-code stub
- Green tests + clean typecheck

## Safety
- Modify only apps/server (adapter, new provider dir, index.ts, types if needed). No web changes, no AGENTS.md, no Notion.
- No git operations (the owner commits).
- Follow AGENTS.md.
