# Task: P2.2 — Implement ClaudeCodeAdapter behind the provider interface (browser-verified)

Phase 2 adds the Claude Code provider. The interface exists (apps/server/src/provider/types.ts, P2.1). The proven patterns are vendored (upstream/t3-code/, especially ClaudeAdapter.ts). The protocol facts are documented with citations in .plans/findings/02-p2.0-claude-code-spike.md. Read all three first.

## Mission
Implement ClaudeCodeAdapter so Glassbox can run a real turn through Claude Code with the same Canvas/trace/decision experience codex already has.

## Design decisions already made (do not relitigate)
- Use the Agent SDK (`@anthropic-ai/claude-agent-sdk` `query()`) exactly like T3 Code. Copy patterns from upstream/t3-code/ClaudeAdapter.ts.
- One claude session = one Glassbox session (thread). Turns ride the same persistent query with resume (resumeSessionAt pattern).
- Permission: mode comes from session opts (the P2.4 panel arrives later; accept it in startSession opts now). Per-request decisions surface through the existing decision flow: an SDK CanUseTool callback defers, Glassbox records a pending decision, /decide resolves it. Never use --dangerously-skip-permissions.
- Event mapping: use the spike's mapping table (assistant text -> agentMessage deltas, tool_use -> item/decision flow, tool_result -> item completed, result -> turnCompleted, etc.). Normalized events must satisfy the existing schema so the reducer and replay work unchanged.
- Trace provenance for this provider is "claude-code-cli" (make the trace store's provenance per-provider, passed by the collector; codex stays "codex-app-server").
- thinking_tokens and rate_limit events are telemetry only: they go to the trace, never become Canvas objects.
- Write scoping: cwd from session opts + permission mode + CanUseTool. No OS sandbox in Phase 2; document the guarantee gap in a code comment.

## Steps
1. Add the SDK dependency to apps/server (@anthropic-ai/claude-agent-sdk). Check the version T3 Code pins and match it.
2. Implement apps/server/src/claude-code/adapter.ts (ClaudeCodeAdapter implements ProviderAdapter). Follow upstream/t3-code/ClaudeAdapter.ts patterns for: query options, CanUseTool deferred pattern, resume state, event normalization, error handling (terminal_reason checks).
3. Wire createAdapter("claude-code") to return it.
4. Make the trace store provenance per-provider (extend makeTraceCollector; codex unchanged).
5. Record a real fixture: run one real harmless turn ("say ready", cwd /tmp) through the new adapter, capture the SDK messages into a fixture file under apps/server/src/claude-code/fixtures/. Unit tests replay this fixture through the normalization path (no live claude needed in vitest).
6. Unit tests: normalization mapping (each claude event type -> expected schema event), resume state handling, permission deferral (simulated CanUseTool resolve), turn completion. Target parity with the codex suite's rigor.
7. Browser verification: add POST /run-provider {provider, cwd, prompt} (or extend the existing run endpoints with a provider param) that runs one turn through claude-code with a readOnly-ish mode (default mode, harmless prompt, cwd /tmp/glassbox-claude-spike). Then Playwright or curl: run it, confirm trace events land with provenance claude-code-cli, derived state populates (task + agent message + result), and a tool_use decision (if any) flows through /decide.
8. Run npx vitest run apps/server/src --reporter=basic (all green) and a typecheck.
9. Append progress to .plans/findings/_p2.2-progress.md as you go.

- No git operations (the owner commits).
