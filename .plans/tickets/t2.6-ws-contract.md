# Task: S2 / T2.6 — HTTP + WebSocket contract + fill item/fileChange schema gap (apps/server)

T2.5 derived state reducer works (41 tests, deterministic replay). Two gaps to fix in this ticket: the reducer does not populate artifacts because item/fileChange is not in the CodexEvent schema, and there is no WebSocket for the web client to subscribe to live events. This ticket adds WS and fills the fileChange gap.

## Goal
1. Add a WebSocket server so a web client can subscribe to a session and receive live decoded events and derived-state updates during a run.
2. Add item/fileChange (not just requestApproval) to the schema and reducer so artifacts populate.

## Steps
1. apps/server/src/codex/schema.ts: add an ItemFileChange schema (threadId, turnId, itemId, changes: [{path, kind, diff}]) for the item/fileChange notification (distinct from item/fileChange/requestApproval). Add it to the CodexEvent union and the dispatch table.
2. apps/server/src/state/reducer.ts: handle ItemFileChange by appending to artifacts.
3. apps/server/src/ws/server.ts: a WebSocketServer on the same HTTP server at path /ws. On connect, the client sends {action:"subscribe", sessionId}. The server then pushes every decoded event for that session as it arrives (live), plus a derived-state snapshot after each event (or after turn/completed). Also support {action:"interrupt", sessionId} from client to trigger adapter.interruptTurn.
4. apps/server/src/index.ts: mount the WS server on the HTTP server. /run-test stays as is (writes trace). Optionally add /run-stream that is like /run-test but also broadcasts to any subscribed WS clients for that sessionId.
5. apps/server/src/ws/server.test.ts: a test that starts the server, opens a WS client, subscribes to a sessionId, triggers a short /run-test for that sessionId, and asserts the client received live events (at least one item/agentMessage/delta and a turn/completed) plus a final derived-state snapshot. Use a readOnly turn so no real file change happens; if no fileChange event fires in a read-only turn, just assert the live event stream and derived-state snapshot work, and add a unit test for the ItemFileChange reducer path with a synthetic event.

## Verify
- WS client subscribed to a session receives live decoded events during /run-test.
- The derived-state snapshot sent at the end has task, finalResult, traceSummary.
- A synthetic ItemFileChange event appended to the reducer populates artifacts.
