# Task: P2.4 — Real-project entry: provider picker, permission panel, repo selection (browser-verified)

Glassbox now has two working providers (codex, claude-code). This slice builds the session-entry experience for real work: the owner picks provider, permission mode, and repo path explicitly in the UI, mirroring T3 Code. The spike findings (.plans/findings/02-p2.0-claude-code-spike.md, Q3 + Q7) document both providers' permission surfaces — read them first.

## Goal
The session entry UI (apps/web) gains a compact setup area before/at run time:
- Provider picker: codex | claude-code (default codex, remembers last choice)
- Permission panel, provider-aware: for codex expose approval policy (untrusted | on-request | never) and sandbox (readOnly | workspaceWrite+path | dangerFullAccess marked as dangerous); for claude-code expose permission mode (default | plan | manual | acceptEdits | auto | bypassPermissions marked as dangerous). Show a one-line description of what each mode allows.
- Repo path input for the writable root (defaults to the demo fixture; validates: path exists, is a directory, is not the Glassbox repo itself, is not ~/.glassbox). Show the resolved path.
- The selected provider + permission mode + repo path must land in the trace provenance of the runs they produce (which mode was active, when), so a run can be reconstructed honestly. Extend the action/session record with a session.configured entry (kind "session.config", provider, permissionMode, repoPath, ts).
- Server: /run-test and /run-demo (and /run-provider if present) accept these options and pass them to the adapter (codex: approvalPolicy/sandboxPolicy; claude-code: permission mode via SDK options). Validate server-side too (same guardrails), never trust the client.

## Steps
1. apps/server: extend the run endpoints + adapters to accept and enforce the options. Guardrails server-side: reject the Glassbox repo path, reject ~/.glassbox, reject non-existent paths (HTTP 400 with a clear message). Record session.config in the trace.
2. apps/web: the session entry UI per the goal. Keep it compact (the header is already busy after S9; consider a collapsible setup row or a small settings popover). Mirror T3 Code's clarity: one control per decision, each with its one-line description. Dangerous modes get a visible warning style.
3. Browser verification (Playwright, extend e2e or new p24.spec.mjs): open the app, pick claude-code + a safe mode (default/plan) + the demo fixture path, run a turn, assert the canvas populates and the trace contains session.config with the chosen mode. Also assert the guardrail: submitting the Glassbox repo path shows a rejection.
4. Full suite: npx vitest run apps/server/src --reporter=basic green; typecheck no new errors.
5. Append progress to .plans/findings/_p2.4-progress.md as you go.
