# Task: S2 / T2.5 — Minimal derived state reducer (apps/server)

T2.4 persists decoded Codex events as Raw Trace. This ticket derives a small state model from those events: the data the Canvas Projector (S3/S4) will read. Derived state is interpretation, re-derivable, and must NOT depend on Canvas layout.

## Glassbox rule
Raw Trace records what happened. Glassbox-derived state interprets it for the product. The reducer may be re-run over a trace and produce the same state. The UI never reads Raw Trace directly for display; it reads derived state. (Notion: Runtime, Codex and Trace; Decision log.)

## Goal
A pure reducer that takes a typed CodexEvent and the current derived state, and returns the next derived state. Plus a replay function that re-runs a whole trace into state. Plus a GET /state/:sessionId endpoint.

## Derived state shape (minimum for P0)
- task: the user instruction (from turn/start input)
- currentWork: the latest in-progress item (from item/started not yet item/completed)
- artifacts: file changes seen so far (from item/fileChange events)
- testResult: the latest test-like item completed (from item/completed where type indicates a test or command with exit code)
- finalResult: from turn/completed (status, durationMs, usage)
- traceSummary: event counts by type, total duration, token usage

Keep the model small. Only add fields the P0 flow needs (task, current work, artifact, test result, final result, trace summary). Do not model Plan, Context, Skill, Tool Config, Eval, Variant, Experiment here (those are P1+).

## Steps
1. apps/server/src/state/types.ts: the DerivedState type and the per-event state shape above.
2. apps/server/src/state/reducer.ts: a pure function reduce(state: DerivedState, event: CodexEvent): DerivedState. Handle each event kind: turn/start sets task; item/started adds to currentWork; item/agentMessage/delta appends to current message; item/fileChange adds to artifacts; item/completed (test-like) sets testResult; turn/completed sets finalResult and traceSummary totals. Unknown events update traceSummary counts only.
3. apps/server/src/state/replay.ts: replayTrace(entries: TraceEntry[]): DerivedState that folds reduce over a loaded trace. This proves reconstruction does not depend on Canvas layout.
4. apps/server/src/index.ts: add GET /state/:sessionId that loads the trace (T2.4 loadTrace) and replays it into DerivedState. Returns the derived state JSON.
5. apps/server/src/state/reducer.test.ts: load a real trace from T2.4 (or run /run-test then GET /state), assert the derived state has: the task text, at least one currentWork or artifact, a finalResult with status and usage, and a traceSummary with correct counts. Also assert that replaying the same trace twice yields identical state (deterministic).

## Verify
- POST /run-test, then GET /state/:sessionId returns a populated DerivedState with task, artifacts/finalResult, traceSummary.
- Replaying the same trace twice produces identical state.
