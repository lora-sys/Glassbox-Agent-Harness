## 5. Codex App Server -- open-source integration path

**GitHub repository:** [github.com/openai/codex](https://github.com/openai/codex) (Apache-2.0, 119k stars)

**App Server is a subcommand** within the Codex CLI repo, not a separate project. The binary is `codex-app-server` (Rust crate at `codex-rs/app-server/`). You run it as:

```bash
codex app-server                        # starts with default stdio transport
codex app-server --listen ws://IP:PORT  # experimental websocket
codex app-server --listen unix://        # unix socket
```

**Source defining the event and approval contract:**  
The canonical source is [codex-rs/app-server/README.md](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md) in the repo. It documents the complete JSON-RPC 2.0 bidirectional protocol.

### Confirmed capabilities

| Requirement | Confirmed? | Evidence |
|---|---|---|
| Lifecycle | Yes | `thread/start`, `thread/resume`, `thread/fork`, `thread/close` methods plus `thread/started`/`thread/closed` notifications |
| Streamed events | Yes | `item/started`, `item/completed`, `item/agentMessage/delta`, `turn/started`, `turn/completed` notifications on stdio |
| Interrupt | Yes | `turn/interrupt` method; turn finishes with `status: "interrupted"` |
| Approvals and permissions | Yes | `item/commandExecution/requestApproval` and `item/fileChange/requestApproval` server-initiated requests; client responds with `{ decision: "accept" \| "decline" \| "cancel" \| "acceptForSession" }` |

**Protocol signature:** JSON-RPC 2.0 (header omitted on wire). Default transport: newline-delimited JSON over stdio. Experimental websocket and unix socket transports also exist. The protocol is bidirectional -- the server can initiate JSON-RPC requests for approvals, attestation, and user input.

**TypeScript types:** Not shipped as a package by OpenAI. A third-party re-distribution exists: `@pwrdrvr/codex-app-server-protocol` (generated from `codex-cli 0.144.0`, 671 `.ts` files, MIT). OpenAI documents types via `codex app-server generate-ts --experimental` but ships them as a per-version generated artifact.

**SDK layer:** The repo also has `sdk/typescript/` (Codex, Thread, Turn classes) and `sdk/python/` (Pydantic wire models, `AppServerClient` with `start()`, `initialize()`, `thread/start`, `turn/start`). These are higher-level wrappers, not the raw JSON-RPC layer.

Sources: [github.com/openai/codex](https://github.com/openai/codex), [codex-rs/app-server/README.md](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md), [openai.com/index/unlocking-the-codex-harness/](https://openai.com/index/unlocking-the-codex-harness/), [github.com/pwrdrvr/codex-app-server-protocol](https://github.com/pwrdrvr/codex-app-server-protocol), deepwiki.com/openai/codex/1.2-repository-structure

## 6. Codex installation and startup

**Installation methods** (from the [Codex CLI README](https://github.com/openai/codex)):

```bash
# npm (global)
npm install -g @openai/codex

# macOS/Linux standalone installer
curl -fsSL https://releases.openai.com/codex/install.sh | sh

# Or download a binary from GitHub Releases
```

**Starting the App Server:**

```bash
codex app-server                          # default stdio
codex app-server --listen ws://0.0.0.0:3456  # websocket (experimental)
codex app-server daemon start              # background daemon (Unix only)
```

**Config/auth:**

- Config file: `$CODEX_HOME/config.toml` (layered: system, user, project)
- Auth: "Sign in with ChatGPT" flow managed by the App Server process itself (via `AuthManager`). The server handles credential state.
- Daemon mode: `codex app-server daemon bootstrap --remote-control` sets up a pidfile-backed backend with Unix domain socket at `$CODEX_HOME/app-server-control/app-server-control.sock`.
- No separate API key config needed for local use -- authentication is handled by the ChatGPT session.

Sources: [github.com/openai/codex](https://github.com/openai/codex), [codex-rs/app-server/README.md](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md), [codex-rs/app-server-daemon/README.md](https://github.com/openai/codex/blob/main/codex-rs/app-server-daemon/README.md)

## 7. tldraw Agent Starter Kit

**GitHub repo (canonical):** [github.com/tldraw/tldraw](https://github.com/tldraw/tldraw) at `templates/agent/`

**Published template repo:** [github.com/tldraw/agent-template](https://github.com/tldraw/agent-template) (MIT, 31 stars)

**Create command:**
```bash
npm create tldraw@latest -- --template agent
```

### What it provides (from tldraw.dev/starter-kits/agent and deepwiki analysis)

Architecture: three areas -- `client/` (React components, agent logic), `worker/` (Cloudflare Worker for model requests), `shared/` (types, schemas).

| Piece | Reusable for Glassbox? | Notes |
|---|---|---|
| `TldrawAgent` class | **Yes** | Central coordinator between LLM and tldraw Editor |
| Canvas context (viewport, shapes) | **Yes** | Extracts simplified shape representations, screenshots for model input |
| Selection context | **Yes** | `AgentContextManager` tracks user's current selection and recent actions |
| Typed Agent actions | **Yes** | `AgentActionManager` with typed tool schemas (align, create, distribute, etc.) validated and sanitized |
| Streamed Canvas updates | **Yes** | Responses stream in real time via `item/agentMessage/delta`-style pattern in the agent pipeline |
| Agent chat panel | **Reference only** | Has a built-in chat UI; Glassbox should build its own rather than adopt this one |
| Cloudflare Worker layer | **Not reusable** | Glassbox will connect to Codex App Server, not a CF Worker |
| `PersistedAgentState` | **Reference only** | Concept of serializing agent memory is relevant but implementation is tldraw-specific |

**Note on reusability:** The Agent starter kit is designed as a self-contained example. Glassbox should reuse the *patterns* (typed actions via schemas, context extraction from the editor, streamed updates) rather than importing the kit code directly, because Glassbox's canvas objects and research semantics are defined independently of tldraw's agent layer.

Sources: [github.com/tldraw/tldraw](https://github.com/tldraw/tldraw), [github.com/tldraw/agent-template](https://github.com/tldraw/agent-template), [tldraw.dev/starter-kits/agent](https://tldraw.dev/starter-kits/agent), deepwiki.com/tldraw/tldraw/6.1-agent-starter-kit

## Summary of key findings

1. **vp v0.2.9 is installed.** Bootstrap via `curl -fsSL https://vite.plus | bash`. Vite+ manages all toolchain binaries per-project.

2. **TanStack stack exists on npm.** `@tanstack/react-router` 1.170.32 and `@tanstack/start` 1.120.20 are current. TanStack Start provides the server/client boundary without Next.js. Note that `@tanstack/start` was last published "a year ago" which may indicate a slower release cadence.

3. **tldraw 5.3.2** is current. The Agent Starter Kit provides reusable patterns for typed canvas actions, context extraction, and streamed updates. The kit is at [github.com/tldraw/agent-template](https://github.com/tldraw/agent-template) and `templates/agent/` in the main tldraw repo.

4. **Effect v4 RC is 4.0.0-rc.112** (npm dist-tag `rc`). The v4 API surface covers all four required features (typed errors, Schema, structured concurrency via Fibers, DI via Layer/Context). The docs at [effect.website/docs/v4/api/effect](https://www.effect.website/docs/v4/api/effect) are a module index only; deeper details require following individual module links.

5. **Codex App Server is a first-class integration path.** It is a subcommand (`codex app-server`) within the open-source [github.com/openai/codex](https://github.com/openai/codex) repo. The protocol is a doc'd, bidirectional JSON-RPC 2.0 API with lifecycle (thread/turn), streamed events, interrupt (`turn/interrupt`), and approvals (command/file change). TypeScript types are generated per-version via `codex app-server generate-ts` or consumed from `@pwrdrvr/codex-app-server-protocol`.

6. **Codex is installed via npm, standalone installer, or GitHub Releases binary.** Auth is handled by the App Server (ChatGPT sign-in). Config lives in `$CODEX_HOME/config.toml`.

7. **This repo is docs-only.** No `apps/`, no `package.json`, no source code to modify.
