## item/fileChange Gap Fix

**Before:** `item/fileChange` was not in the `CodexEvent` union. The dispatcher's `METHOD_TAG` had only `item/fileChange/requestApproval`. The reducer had no case for file changes, so `state.artifacts` was always `[]`.

**After:** The `item/fileChange` method maps to `_tag: "itemFileChange"`. The reducer handles it:

```ts
case "itemFileChange": {
  counts["item/fileChange"] = (counts["item/fileChange"] ?? 0) + 1;
  const changes = event.changes.map((c) => ({
    path: (c as { path: string }).path,
    kind: (c as { kind: string }).kind,
    diff: (c as { diff?: string }).diff ?? null,
  }));
  return {
    ...state,
    artifacts: [...state.artifacts, { itemId: event.itemId, changes, status: "changed" }],
    traceSummary: { ...state.traceSummary, eventCounts: counts, totalEvents: state.traceSummary.totalEvents + 1 },
  };
}
```

`item/fileChange/requestApproval` still maps to `requestApproval` (unchanged).

**Test:** 4 reducer unit tests confirm: artifact population, multi-batch accumulation, traceSummary counting, and currentWork preservation.

## WebSocket Protocol

**Endpoint:** `ws://host:3030/ws?sessionId=<id>` (handshake query string).

**Messages client → server:**

```json
{"action": "subscribe", "sessionId": "<id>"}
{"action": "interrupt", "sessionId": "<id>"}
```

**Messages server → client:**

| type | payload | when |
|------|---------|------|
| `subscribed` | `{ sessionId }` | on successful subscription |
| `event` | `{ event: { method, params } }` | each decoded Codex event during a run |
| `derivedState` | `{ derivedState: { task, currentWork, artifacts, testResult, finalResult, traceSummary } }` | after turn/completed + replay |
| `sessionEnded` | `{ sessionId }` | when the run finishes |
| `error` | `{ message }` | unknown action, missing sessionId |

**Session isolation:** Broadcasts are keyed by `sessionId`. A broadcast to `session-A` never reaches subscribers of `session-B`.

**Interrupt via WS:**
- Client sends `{"action":"interrupt","sessionId":"<id>"}`.
- Server calls `adapter.interruptTurn(currentThreadId, currentTurnId)`.
- Client receives `{"type":"interrupted","sessionId":"<id>"}`.

## How to Subscribe and Run

```bash
# 1. Start the server
cd apps/server
npx tsx src/index.ts

# 2. In a separate terminal, open a WebSocket
ws://localhost:3030/ws?sessionId=my-session-123

# 3. Trigger a run (this returns sessionId and also streams to WS live)
curl -X POST http://localhost:3030/run-test \
  -H "content-type: application/json" \
  -d '{"prompt":"say hello"}'

# 4. Receive live events on the WS:
#    - "subscribed" ack
#    - "event" for each decoded Codex notification
#    - "derivedState" snapshot after turn completes
#    - "sessionEnded" when done
```

Alternatively, `POST /run-stream` (same as `/run-test` but the run is designed for WS-first consumption; the derived-state snapshot is sent at the end so the client doesn't need to poll `/state/:sessionId`).

To interrupt from the client:
```json
{"action":"interrupt","sessionId":"my-session-123"}
```
