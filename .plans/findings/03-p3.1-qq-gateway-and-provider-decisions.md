# QQ 接入与提供商复用方案

日期为 2026-09-12。状态为 Planned。本轮只更新文档和参考源码，没有接入 QQ 或 Pi 运行代码。源码复用方式已按最新要求调整为复制到项目目录，以 [复用清单](03-p3.2-source-reuse-map.md) 和 Plan 03 为准。

## 产品顺序

先在 Windows 上做通过 QQ 群 @和本人私聊使用的个人助理，再开放给其他用户保存自己的内容，之后增加细粒度权限。macOS 和 Linux 从代码设计上保持可移植，后续分别验证。桌面打包和跨设备同步尚未决定。

复杂角色可以延后，可信身份绑定、本人白名单、指定测试群、个人数据与群上下文隔离从第一版开始。群消息的可见范围约束模型上下文和工具结果，即使发起人是本人也不能把私人资料送进群。

## 两种 QQ 入口

用户要求同时考虑 NapCat 和 QQ 官方机器人。结合自用测试群和主动推送需求，当前建议先接 NapCat 的 OneBot 接口，同时保留 SnowLuma 的 OneBot 兼容验证，再以同样的领域接口接入官方机器人。这是当前实施建议，不表示两个入口已经实现。

- 每个入口记录连接 ID、机器人身份、群 ID、调用者 ID 和消息 ID。QQ 官方应用 ID 与 OneBot QQ 号不自动互认，昵称不能证明身份。
- 普通回复使用收到消息的连接。主动推送使用明确配置的入口和目标，不从正文猜测目标。
- 同一目标指定默认发送入口，不同时从两种入口发送同一任务结果。
- 跨入口合并身份或群需要验证，不假设底层消息 ID 可以跨入口对应。
- 忽略自身和其他机器人产生的消息，防止互相触发。
- 不通过另一个入口绕过官方发送限制。

推送记录包含投递 ID、目标、触发来源、必要的去重标识、尝试次数和结果。重复事件不能生成重复任务。已确认的发送不重发，明确失败可以有限重试，超时但结果未知时不能盲目补发。NapCat 掉线需要重新连接或登录，后台任务状态与消息投递状态分别保存。

NapCat 作为独立外部连接使用，不把其源码合入或打包进 Glassbox。当前检出的 LICENSE 是 Limited Redistribution License，包含非商业使用和修改发布限制。接入协议不意味着取得复制或分发其源码的许可。参见 [NapCat 源码许可证](../../upstream/repos/NapCatQQ/LICENSE) 和 [OneBot 接口文档](https://napneko.github.io/develop/api)。

## 提供商与执行方式

当前源码中的包名为 `@earendil-works/pi-ai` 和 `@earendil-works/pi-agent-core`，两个 package.json 的版本均为 0.85.1。实现时选定兼容版本并锁定依赖，不使用已过时的包名。

Pi 的提供商与 Agent core 实现按需复制到项目目录，携带必要依赖闭包并改写内部包引用，不以安装完整 Pi 框架替代源码复用。Glassbox 提供授权上下文与受保护工具包装，保存身份、Conversation 和 Trace。普通基础 SDK 保持依赖管理。

项目核心执行以 PI 为主，API 可扩展，模型多配置。agy-staff 为当前执行主线。不再接入本机外部执行适配器。真实模型集成测试通过配置的 API 运行，确定性权限与持久化测试使用假工具和一次性数据库。

OpenHarness 当前核心为 Python。可以复用其独立执行能力、配置流程和经过检查的代码，不把整套 Python 提供商层重新翻译成 TypeScript。优先使用已有包、进程协议或小范围移植，逐个记录源文件和许可证。

源码依据如下：

- [Pi 模型包](../../upstream/repos/pi/packages/ai/package.json)
- [Pi Agent core](../../upstream/repos/pi/packages/agent/README.md)

本地参考 checkout 不随 Glassbox 的 Git 提交分发，其他机器需要按 [上游清单](../../upstream/manifest.json) 获取相同版本。

## 用户内容

开放给其他成员时，个人记录默认归本人，群共享记录需要明确保存为群可见。两者保留作者和来源。个人上下文不能复制给新用户，也不能因为本人在群里提问就向群公开。先实现可检查的保存、读取和删除，再讨论自动学习。

具体执行顺序和每阶段验收以 [Plan 03](../03-personal-agent-foundation.md) 为准。
