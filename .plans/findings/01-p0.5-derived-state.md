# S2 / T2.5 Findings — Minimal Derived State Reducer

## DerivedState Shape

```ts
interface DerivedState {
  task: string;                  // from turn/start input
  currentWork: CurrentWork | null;
  artifacts: ArtifactChange[];
  testResult: TestResult | null;
  finalResult: FinalResult | null;
  traceSummary: TraceSummary;
}

interface CurrentWork {
  itemType: string;
  itemId: string;
  text: string;
  phase: string | null;
  startedAtMs: number;
}

interface ArtifactChange {
  itemId: string;
  changes: unknown[];
  status: string;
}

interface TestResult {
  itemType: string;
  itemId: string;
  status: string;
  exitCode: number | null;
  aggregatedOutput: string | null;
  durationMs: number | null;
}

interface FinalResult {
  status: string;
  startedAt: number;
  completedAt: number;
  durationMs: number;
  error: string | null;
}

interface TraceSummary {
  eventCounts: Record<string, number>;
  totalEvents: number;
  totalDurationMs: number | null;
  tokenUsage: { promptTokens: number | null; completionTokens: number | null; totalTokens: number | null };
}
```

## Event Kinds the Reducer Does NOT Yet Handle

| Event | Gap | Notes |
|---|---|---|
| `item/fileChange` | No decoded event in CodexEvent union | The schema only defines `item/fileChange/requestApproval` (→ `requestApproval` tag). File change data from provider notifications is not captured by the current Effect Schema decoder. Raw trace entries with `method: "item/fileChange"` are counted in the summary but do NOT populate `artifacts`. |
| Token usage in finalResult | Turn completed error field | The provider's `turn/completed` error field is typed as `Schema.Unknown` (erased at decode time). Currently serialized as JSON string. If the provider sends structured usage data alongside the turn, it would need a separate schema field. |
| Usage tokens | No usage field in TurnCompletedParams | `usageTokens`, `totalTokens` are reported in `RunTestSummary` by the adapter but the `TurnCompletedParams` schema doesn't extract them. TraceSummary.tokenUsage stays null until the schema adds usage fields. |

## Deterministic Replay Verified

`replayEntries()` applied to the same synthetic trace 3 times produces identical `DerivedState` objects (`toEqual` passes). No mutable global state, no timing dependencies, no Canvas layout involved.

## How to Call

```bash
# 1. Start the server
cd apps/server && PORT=3030 node --experimental-strip-types src/index.ts

# 2. Run a turn (POST /run-test)
curl -s -X POST http://localhost:3030/run-test \
  -H "content-type: application/json" \
  -d '{"prompt": "say hello"}'
# → { "sessionId": "ca3b…", "threadId": "…", "turnId": "…", "turnStatus": "completed", … }

# 3. Get derived state (GET /state/:sessionId)
curl -s http://localhost:3030/state/<sessionId>
# → { "sessionId": "ca3b…", "derivedState": { "task": "say hello", "currentWork": null, …, "traceSummary": { … } }, "replay": { … } }
```
