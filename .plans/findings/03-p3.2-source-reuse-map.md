## 复用约定

参考仓不参与生产 import、workspace、构建、类型检查或打包。选中的实现复制到 apps/server/src 下由 Glassbox 维护，内部包引用改成项目内引用。每次复制保存 SOURCES.md、上游提交、原路径、许可证、NOTICE 和本地改动说明。运行代码不依赖安装完整外部框架包。

外部 SDK、数据库驱动、ws、TypeScript、Vite+ 等基础依赖仍按正常依赖管理。复制上游业务实现不意味着自行实现 HTTP、数据库引擎或编译器。跨语言不兼容的部分按上游机制适配，复用其输入、输出、状态转换与测试案例。

复制清单需要包括静态与动态 import 的依赖。先做离线编译和固定事件测试，再进入真实 Provider 测试。不要把一份可读源码当作已独立可运行的模块。

## QQ 协议实现的选择

SnowLuma 与 NapCat 均作为外部 OneBot 实现，Glassbox 写一个符合协议的渠道适配器，不各造一套 Agent。先以 NapCat 完成 Windows 群 @ 和私聊验收，再使用相同协议测试 SnowLuma，分别记录兼容结果。不能因为都叫 OneBot 就声称所有媒体和扩展动作一致。

SnowLuma 的 README 声明支持 OneBot v11 动作和事件、多账号、WebSocket、HTTP、SDK 与 MCP。参考边界包括 packages/onebot 与 packages/sdk。当前提交为 fb5f9b21558134db8803d216dfc19c6bce11f2c0。

SnowLuma 的 LICENSE 是源码可见非商业许可，公开修改版或衍生版需要事先授权，原生附加组件另有许可。NapCat 同样有自定义限制。当前方案不复制、改写或打包这些受限源码到 Glassbox，协议适配依据公开标准与获得许可的实现材料。外部接入不自动解决其运行和分发许可条件。

QQ 官方机器人是独立 adapter，不能把官方应用内的 openid 与 OneBot QQ 号自动合并。不自动切换渠道绕过平台发送限制。接入时依据实际能力决定进度消息、附件和主动通知的表现。

## 工具链依据

当前项目仍是 npm workspaces、Vite 7、Vitest 3，未安装 Vite+。按 [Vite+ 官方迁移说明](https://viteplus.dev/guide/migrate)，从 workspace 根迁移，先核对 Vite 8 与 Vitest 4.1 的兼容前提，统一更新锁文件、Vite alias、Vitest 版本、脚本和配置。使用 no-agent 选项保留项目自有 AGENTS。

vp check 的类型检查需要配置启用 typeCheck，不能仅看到命令成功就宣称完成类型检查。依据 [Vite+ check 文档](https://viteplus.dev/guide/check)。迁移后执行现有前后端构建与固定测试，不让工具链迁移夹带产品重写。

Turso 驱动按照 [官方 TypeScript 参考](https://docs.turso.tech/sdk/ts/reference) 验证。trajectory-panel 使用的 libsql 客户端属于兼容路线，新的本地引擎驱动与它不是同一个引擎。本阶段先沿用其本地文件接口完成事务和重开验证，保留窄 Domain API，不把跨设备同步作为前置依赖。
